# 运行时系统设置设计

## 1. 背景与目标

当前应用从 `configs/config.yaml` 加载配置，`utils.config.get_config()` 使用进程内缓存。配置修改后必须重启服务才能生效，也没有面向管理员的可视化编辑入口。

本功能在现有静态前端中增加受密码保护的“设置”弹窗，使管理员可以修改指定业务配置。保存结果仍写入唯一的 `configs/config.yaml`，并对后续新请求和新任务即时生效。

核心约束：

- 只使用一份 `configs/config.yaml`，不增加运行时覆盖文件或配置数据库。
- 设置密码以明文保存在 `config.yaml`，只允许人工修改，不通过 API 返回或更新。
- API Key 等敏感字段只能查看配置状态、覆盖或清除，不能读取原文。
- MySQL、Milvus 和 server 配置不开放给前端，也不能通过设置 API 修改。
- 保存后，新请求和新任务使用新配置；已运行任务不强制切换配置。

## 2. 开放范围

设置页开放以下九组配置：

1. `mineru`：全部字段。
2. `chunking`：全部字段。
3. `embedding`：`base_url`、`api_key`、`model_name` 可编辑；`embedding_dim`、`batch_size`、`timeout`、`retry_count` 只读。
4. `extraction`：全部字段。
5. `table_name_validation`：全部字段，保持独立于 `extraction` 的覆盖配置语义。
6. `analysis`：全部字段。
7. `vl_model`：全部字段。
8. `web_search`：全部字段。
9. `storage`：全部字段。

禁止通过设置 API 读取或修改：

- `server`
- `mysql`
- `milvus`
- 设置密码与会话安全参数
- 未知分组、未知字段和只读字段

后端使用显式请求模型表达白名单，不接受任意 YAML 路径或无结构字典。提交禁止字段时返回 `422`，不静默忽略。

## 3. 配置模型

在 `AppConfig` 中增加后端专用设置安全配置，例如：

```yaml
settings:
  password: "change-me"
  session_minutes: 30
  secure_cookie: false
```

- `password` 是明文管理员密码。
- `session_minutes` 默认 30 分钟。
- `secure_cookie` 用于 HTTPS 部署；启用后会话 Cookie 带 `Secure`。
- 整个 `settings` 分组不出现在配置读取响应中，也不能由配置更新接口修改。

配置管理模块负责：

- 获取当前不可变 `AppConfig` 快照。
- 在进程内原子替换当前配置引用。
- 读取原始 YAML，保留未开放分组和值。
- 合并管理员提交的配置变更。
- 完整 Pydantic 校验。
- 原子写回 `config.yaml`。
- 计算配置版本。

不采用“每个请求重新读取 YAML”，以避免重复磁盘 I/O 和写入时序问题；也不增加文件监听器。人工修改 YAML 仍在下次启动时生效。

## 4. 热更新语义

保存成功后，配置管理模块整体替换内存中的 `AppConfig` 对象。业务代码后续调用 `get_config()` 时取得新对象。

需要调整现有 `lru_cache` 单例，使配置对象能够被显式替换，同时保证读取方始终看到一个完整、验证通过的对象，不能看到半更新状态。

热更新边界：

- MinerU、分块、向量 API 地址/密钥/模型、字段提取、表格名校验、逻辑分析、VL、网络搜索和存储参数对后续调用生效。
- 正在运行的任务可以继续使用其当前阶段已经取得的配置快照，不保证同一任务中途切换。
- `vl_model.global_max_concurrency` 更新后，重建 VL 并发控制器；已经占用旧控制器的调用自然结束。
- `embedding.embedding_dim` 不允许前端修改，避免与现有 Milvus collection 维度冲突。
- MySQL 和 Milvus 客户端不参与热更新。

如果未来以多 worker 方式部署，进程内更新不能自动广播到其他 worker。本期应用继续采用当前单 worker 模式；多 worker 配置广播不在本期范围内。

## 5. 写盘事务与并发控制

保存流程：

1. 验证管理员会话。
2. 验证请求字段白名单和配置版本。
3. 在进程级异步锁内重新读取当前 YAML。
4. 合并普通字段和密钥操作。
5. 用完整 `AppConfig` 执行类型、范围和交叉字段校验。
6. 预构造新配置需要的运行时控制器，确保后续引用切换不会失败。
7. 将完整配置写到同目录临时文件并刷新文件缓冲。
8. 使用原子替换覆盖 `config.yaml`。
9. 切换内存配置和预构造控制器的引用。
10. 返回新配置版本和脱敏配置。

YAML 写入采用能保留注释、顺序和未知节点的 round-trip 方式。未开放的 MySQL、Milvus、server、settings 等分组必须原样保留，不能因前端保存而丢失。

写盘或校验失败时不替换原文件，不切换内存配置。临时文件尽力清理，失败记录不含密钥的错误日志。

配置读取响应包含 `version`。前端保存时提交 `base_version`；如当前版本已变化，后端返回 `409`，要求重新加载，避免两个管理员互相覆盖。

版本由规范化后配置内容的哈希生成，不包含在 YAML 中额外维护。

## 6. 密钥协议

敏感字段至少包括：

- `embedding.api_key`
- `extraction.llm_api_key`
- `table_name_validation.llm_api_key`
- `vl_model.api_key`
- `web_search.api_key`

读取响应不返回原值，也不返回可被误当成原值的掩码字符串。每个密钥返回状态：

```json
{
  "configured": true
}
```

更新请求对密钥使用明确操作：

```json
{
  "action": "keep"
}
```

```json
{
  "action": "replace",
  "value": "new-secret"
}
```

```json
{
  "action": "clear"
}
```

- `keep` 保留磁盘中的当前值。
- `replace` 要求非空新值并覆盖旧值。
- `clear` 明确写入空字符串或 `null`，按对应配置模型定义处理。
- 普通配置响应、异常响应和日志均不得包含密钥或设置密码。

## 7. 管理员会话

设置路由提供登录、会话状态、读取配置、保存配置和退出登录能力。

登录成功后：

- 使用密码学安全随机数生成不透明令牌。
- 服务端只保存令牌摘要、创建时间和过期时间。
- 浏览器通过 `HttpOnly` Cookie 携带令牌。
- Cookie 使用 `SameSite=Strict`，路径限制到设置 API，最大有效期默认 30 分钟。
- `secure_cookie=true` 时附加 `Secure`。
- 退出登录立即吊销会话并清除 Cookie。

会话存储为单进程内存结构，进程重启后所有设置会话失效。该行为符合当前单 worker 部署方式，不引入数据库表。

登录失败限速：

- 按客户端 IP 记录失败次数。
- 连续 5 次失败后锁定 5 分钟。
- 密码错误统一返回相同提示，不泄露密码配置细节。
- 成功登录后清除该 IP 的失败计数。
- 比较密码时使用恒定时间比较函数。

## 8. API 设计

建议新增 `/settings` 路由：

- `POST /settings/login`：验证密码，创建会话 Cookie。
- `GET /settings/session`：返回当前会话是否有效，不返回配置。
- `GET /settings/config`：返回白名单范围内的脱敏配置、只读元数据和版本。
- `PATCH /settings/config`：提交差量变更、密钥操作和 `base_version`。
- `POST /settings/logout`：吊销当前会话并清除 Cookie。

所有配置读取和写入接口都要求有效会话。响应继续使用项目现有 `ResponseWrapper`；鉴权失败使用实际 HTTP `401`，限速使用 `429`，版本冲突使用 `409`，请求校验失败使用 `422`，写盘失败使用 `500`。

`GET /settings/config` 同时提供字段元数据，或由前端维护固定表单定义。本期优先由前端维护稳定的显示名称、单位和帮助文本，后端只返回值、密钥状态、只读字段和值类型，减少后端与展示层耦合。

## 9. 前端交互

入口位于页面头部文档类型区域，在现有“管理”按钮右侧增加带设置图标的“设置”按钮：

```text
项目 [选择器]  文档类型 [选择器]  [管理] [设置]
```

点击行为：

1. 检查设置会话。
2. 会话无效时显示密码弹窗。
3. 登录成功后读取脱敏配置并打开系统设置弹窗。

设置界面复用现有静态 HTML、JavaScript、CSS 和 Lucide 图标，不增加前端框架。弹窗采用单栏内容和分组导航，包含九个配置分区。使用数字输入、开关、普通文本框和 JSON 文本区等与数据类型匹配的控件。

向量化分组中，只有地址、API Key 和模型名可编辑，其余参数以只读样式显示。

密钥控件显示“已配置/未配置”，提供“更新”和“清除”操作，不渲染旧值。

底部固定保存栏展示未保存状态。前端先做必要的格式和范围校验，后端仍是最终校验者。

保存成功后更新本地版本并提示“已即时生效”。会话过期时保留尚未保存的表单内容，重新登录后先检查版本；版本未变则继续保存，版本已变则提示重新加载和重新应用修改。

本期不提供配置历史、版本回滚、多人审批或设置密码修改页面。

## 10. 错误处理

- 登录失败：统一提示“密码错误或暂时无法登录”。
- 登录限速：提示稍后重试，不显示服务端密码信息。
- 会话过期：返回 `401`，前端重新验证且保留未保存内容。
- 非白名单、未知字段或只读字段：返回 `422` 并指出字段路径。
- 配置版本冲突：返回 `409`，前端提示配置已被其他管理员修改。
- Pydantic 校验失败：返回字段级错误，前端定位到对应分组和输入项。
- YAML 写入失败：保留磁盘和内存中的旧配置，返回保存失败。
- VL 控制器构造失败：发生在原子替换前，保存事务终止，不改变磁盘和内存配置。

## 11. 测试策略

后端测试覆盖：

- 正确密码登录、错误密码、恒定响应语义、30 分钟过期、退出和失败限速。
- 未登录不能读取或保存配置。
- 读取响应不含设置密码、MySQL、Milvus、server 和任何密钥原文。
- 每种密钥的保留、替换和清除。
- 白名单限制、未知字段拒绝、向量只读字段拒绝。
- Pydantic 校验错误不改变文件或内存配置。
- 临时文件写入/原子替换失败时回滚。
- `base_version` 冲突返回 `409`。
- 保存后各开放服务对后续调用读取新配置。
- VL 并发数更新后使用新控制器。
- YAML 注释、字段顺序和未开放配置保存前后一致。

前端测试或浏览器验证覆盖：

- “设置”按钮位于“管理”右侧。
- 密码弹窗、错误提示、登录成功、退出和会话过期流程。
- 九个配置分组完整展示。
- 向量化只开放地址、API Key 和模型名。
- 密钥只显示状态，更新和清除操作生成正确请求。
- 未保存状态、保存成功、字段错误和版本冲突提示。
- 桌面和窄屏下弹窗无内容重叠，字段文字和操作按钮不溢出。

## 12. 非目标

- 不开放 MySQL、Milvus 或 server 配置。
- 不改变数据库或 Milvus 客户端的生命周期。
- 不支持多 worker 配置广播。
- 不支持从前端修改设置密码。
- 不提供密钥查看、导出或复制功能。
- 不实现配置历史、回滚、审计数据库或审批流程。
- 不监控人工修改的 YAML 并自动热重载。
