# 逻辑分析调试临时重新抽取设计

## 背景

逻辑分析调试当前只从 `extraction_result` 读取依赖字段值。用户保存新的抽取字段配置后，如果没有重新运行文件抽取阶段，库中可能没有对应结果，规则调试会因依赖字段为空而失败。

本功能在规则调试面板增加一个单次开关。开启后，调试请求使用当前已保存的抽取字段配置重新抽取当前规则所需字段，并直接使用本次结果执行规则；结果不写数据库，也不修改文件处理进度。

## 目标

- 规则调试面板提供“重新抽取依赖字段”开关。
- 开关默认关闭，不保存设置，重新进入调试模式时恢复关闭。
- 开启后只抽取当前规则依赖字段，以及进阶字段运行所需的前置普通字段。
- 本次抽取结果只存在于当前请求内，不写入 `extraction_result`。
- 规则分析只使用本次抽取结果，不与数据库旧结果混用。
- 页面展示抽取进度和每个字段的完整调试结果。
- 开关关闭时保持现有接口和事件行为。

## 非目标

- 不重新运行 parsing、tableing、chunking 或 embedding 阶段。
- 不修改文件的 `progress` 或任何阶段时间戳。
- 不提供持久化开关设置。
- 不自动保存规则编辑表单或抽取字段配置。
- 不替代正式的文件重新抽取流程。

## 用户交互

规则调试面板的文件选择器下方增加“重新抽取依赖字段”开关，默认关闭。

关闭时，点击“测试”继续直接读取已落库抽取结果。开启时，点击“测试”后页面按以下顺序工作：

1. 显示“正在重新抽取依赖字段”。
2. 展示字段级进度和本次抽取结果。
3. 全部必需字段成功且非空后，展示规则实际收到的依赖字段值。
4. 继续现有表达式解析、网络搜索、LLM 调用和结果展示。

新增“本次抽取结果”区块。每个字段展示：

- 字段名和字段 ID
- 成功或失败状态
- 抽取值
- 抽取理由
- 可用页码 `source_pages`

前置字段也展示在该区块中，并通过顺序和字段身份与规则直接依赖字段区分；规则的“依赖字段值”区块仍只展示规则直接依赖。

测试运行期间禁用文件选择器、开关和测试按钮，避免同一面板内修改请求上下文。运行结束后恢复控件。

## API 契约

`AnalysisTestRequest` 增加：

```json
{
  "re_extract": false
}
```

字段为布尔值，默认 `false`，因此旧调用方无需修改。

本页面使用的 `POST /analysis/test/stream` 在 `re_extract=true` 时，于现有规则调试事件前增加：

- `extraction_started`: 临时抽取开始，包含待抽字段总数。
- `extraction_field`: 单字段完成，包含 `field_id`、`field_name`、`value`、`reason`、`pages`、`source_pages`、`success`、`index` 和 `total`。
- `extraction_done`: 临时抽取结束，包含总数、成功数和失败数。

之后继续现有 `input_values`、`resolved_expression`、可选的 `web_search`、`prompt`、`llm_response`、`result`、`done` 事件。

若字段配置缺失、字段不属于所选文件的文档类型、抽取失败或直接依赖字段最终为空，则发送现有 `error` 事件并终止，不发送规则分析阶段事件。错误信息列出具体字段。

非流式 `POST /analysis/test` 同样接受 `re_extract`。开启时使用相同的临时抽取服务，并在失败时返回明确的 4xx 错误；成功响应保持现有形状，不额外返回持久化状态。

## 后端设计

### 临时依赖抽取服务

在抽取服务边界内新增一个面向调试的临时抽取入口，输入为 `file_id`、规则直接依赖字段 ID 列表和数据库会话，输出为字段级结果流以及最终内存字段值映射。

服务执行以下步骤：

1. 查询文件并确定 `type_id`。
2. 仅从该 `type_id` 加载规则直接依赖的字段配置。
3. 对进阶字段解析其引用配置，补齐运行需要的前置普通字段；校验所有引用均存在于同一文档类型。
4. 按正式抽取语义排序：普通字段优先，进阶字段随后；组内继续使用现有并发限制。
5. 一次性加载所需文件内容、表格、分块和可选向量索引快照。
6. 复用 `_extract_field_result`、正式抽取的成功校验、来源排序和页码派生逻辑。
7. 将结果聚合到请求内的 `field_values`、页码和展示数据中，不调用 `_persist_field_computation`，不执行 `session.add`、更新或 `commit`。

为避免持久化逻辑与结果整形继续耦合，现有 `_persist_field_computation` 中纯计算部分应拆成可复用的结果整形函数：负责来源排序、`source_pages` 派生、普通字段内存映射更新和对外 item 组装；正式流程在整形前后保留数据库 upsert，临时流程只调用整形部分。

临时流程继续复用全局和单文件抽取并发限制。无论正常结束、业务失败还是客户端取消，都必须注销本次任务限流器并取消未完成任务。

### 规则调试集成

规则路由先完成现有规则配置解析，再根据 `re_extract` 选择字段来源：

- `false`: 保持现状，从 `extraction_result` 查询所有字段值。
- `true`: 运行临时依赖抽取，使用返回的内存映射，不查询或合并旧抽取值。

规则执行核心接收已解析的 `field_values`，避免内部再次固定查询数据库。流式和非流式接口共用同一个字段来源准备函数，防止两条接口行为漂移。

## 错误处理

- 文件不存在：返回 404 或在流建立后发送 `error`。
- 依赖字段配置不存在或类型不匹配：终止并列出字段 ID。
- 单字段抛错：保留该字段的失败原因和已完成字段的展示结果；必需字段存在任何失败时不执行规则。
- 直接依赖字段抽取值为空：视为调试失败，不回退数据库旧值。
- 前置字段失败导致进阶字段无法执行：两个字段均在结果区展示可排查原因。
- 客户端取消：取消未完成抽取任务，释放限流器，不产生数据库写入。

## 前端设计

- `buildRuleDebugPanel()` 渲染开关和“本次抽取结果”区块。
- `runRuleTest()` 将开关值作为 `re_extract` 放入请求；开关关闭时显式发送 `false`。
- 新增事件渲染分支处理 `extraction_started`、`extraction_field` 和 `extraction_done`。
- `extraction_field` 到达即按配置序号更新固定结果行，完成顺序不会造成列表跳动。
- 结果文本全部经过现有 HTML 转义工具。
- 调试结果重置时同时清空临时抽取区块；退出并重新进入调试模式后开关恢复关闭。
- 样式复用现有调试区块、结果行和状态颜色，只为开关布局和字段状态补充必要样式。

## 测试

后端测试覆盖：

- `re_extract` 默认值为 `false`，旧请求行为不变。
- 开启时只加载规则依赖字段及必要前置字段。
- 临时抽取复用正式抽取结果语义和并发限制。
- 临时抽取不新增、覆盖或删除 `extraction_result`，不提交会话，不修改文件进度。
- 内存新值与数据库旧值冲突时，规则只使用内存新值。
- 字段失败或直接依赖值为空时停止规则执行，并提供具体错误。
- 进阶字段能使用同次请求内前置字段的值和页码。
- SSE 新事件顺序正确；关闭开关时事件序列不变。
- 非流式接口与流式接口字段来源语义一致。

前端测试或静态行为测试覆盖：

- 开关默认关闭且请求携带正确布尔值。
- 重新进入调试模式后开关复位。
- 抽取进度事件正确创建和更新字段结果行。
- 结果展示包含字段名/ID、状态、值、理由和可用页码。
- 调试期间相关控件禁用，结束或失败后恢复。

## 兼容性与安全性

- 新请求字段有默认值，现有 API 消费者不受影响。
- 新 SSE 事件只在显式开启时出现；现有前端对未知事件本来也会忽略。
- 临时抽取不写数据库，因此不会改变正式管线结果、回调契约或文件状态。
- 文档类型隔离在字段配置加载阶段强制执行，不能跨类型借用字段配置。
